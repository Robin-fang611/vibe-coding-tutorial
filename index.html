    课程 / 认知篇

    第 1 章 · 课程导论：什么是 Vibe Coding

    🎯 本章学习目标：能用自己的话解释 Vibe Coding；说清它和传统学编程的区别；破除"完全不用动脑"的误解；建立最基础的计算思维。

    1.1 一个真实的场景

    小林想转行做产品经理，想做个作品集网站投简历，但"我从没写过代码"。过去这意味着：先学半年编程，再学框架，再学部署——大多数人卡在第 2 周就放弃了。

    现在，小林打开 WorkBuddy，输入："帮我做一个个人作品集单页，我叫小林，想转行做产品经理，要简洁专业风格。" 几十秒后，一个能看的网站出现了。她再一句句提修改，最后免费上线。这就是 Vibe Coding。

    1.2 它到底是什么

    你可以这样理解：AI 就是一个能和你打字聊天的程序。你用平时说话的中文描述想要什么，它帮你把代码写出来；你看着效果用大白话提意见，它再改。你完全不需要先学编程语法。

    一句话定义：Vibe Coding = 你当产品经理 + 验收员，AI 当程序员。你负责"想清楚要什么 + 判断好不好"，AI 负责"把它写成能运行的代码"。

    1.3 它 vs 传统学编程（诚实对比）

    维度传统路径Vibe Coding
    顺序语法→框架→项目（易半途而废）先做出来→遇到不懂再补原理
    门槛常卡在"环境配置"很多工具零安装，打开即用
    核心能力写代码表达需求 + 验收效果
    短板慢但基础扎实快但需懂"怎么问"与基本原理
    借鉴 The Odin Project 的诚实：Vibe Coding 不让你"瞬间变成工程师"，但它让你从"被技术拒绝的人"变成"能用技术实现想法的人"。这正是零基础最需要的突破口。

    1.4 常见误解

    • ❌ "完全不用动脑" → 错。你越能说清要什么，结果越好。
    • ❌ "以后不用学编程了" → 错。懂原理能让你指挥得更准、排错更快。
    • ❌ "AI 写错的也要照收" → 错。你是验收员，不对就让它改。

    1.5 计算思维启蒙（借鉴 CS50）

    CS50 最强调的一点：编程本质是把模糊的目标拆成清晰的步骤。Vibe Coding 也一样——你给 AI 的需求，越接近"步骤化"，它越稳。

    小练习（热身用，不强求）：把你"想要的作品集"先拆成几个模块（例如：自我介绍、关于我、技能、联系方式）写在纸上，心里有个数即可。第 5 章的需求生成器会自动帮你组织成发给 AI 的文案——所以不用怕"白写"；本章拆模块只是让你提前想清楚到底要什么，第 6 章实战生成时也可对照检查。
    课程 / 认知篇

    第 2 章 · 计算机常识速览（原理基底）

    🎯 学习目标：理解"项目=文件夹"、"网页怎么跑起来"、HTML/CSS/JS 三剑客各自干嘛、本地与线上的区别；记住本章术语表。
    写给纯小白：本课程假设你没有任何基础。任何专业名词（服务器、命令行、GitHub、API……）第一次出现，都会用大白话解释。看到不懂的词先别慌，往下读就有答案——你不是一个人在面对这些词。

    2.1 你的项目，就是一个文件夹

    你在电脑里建过文件夹吧？一个网站项目，本质就是一个文件夹，里面装着若干个文件：

    我的作品集/
├─ index.html   ← 主页（网站的大门，默认打开它）
├─ style.css    ← 样式（颜色、排版、好不好看）
└─ script.js    ← 交互（点击、动画等"会动"的部分）
    原理：电脑里一切都是"文件"。代码不是魔法，就是带特殊语法的文本文件，用对的软件打开就会"活"起来。

    2.2 网页是怎么跑起来的（借鉴 MDN）

    你每天刷的网页，背后是：浏览器（Chrome/Safari）向一台"服务器"发出请求，服务器把 index.html 发回来，浏览器再把它画出来。

    类比（借鉴 CS50 比喻法）：服务器像餐厅厨房，index.html 像菜谱，浏览器是服务员——把菜谱（代码）端给你，并按菜谱把"菜"（页面）做出来摆在你面前。

    2.3 三剑客：HTML / CSS / JavaScript

    角色干嘛的生活类比
    HTML结构 / 内容（有哪些块、什么文字）房子的框架与户型图
    CSS样式 / 长相（颜色、字体、间距）房子的装修（刷墙、摆家具）
    JS交互 / 行为（点击、切换）房子的电路与开关
    记住这个比喻，全程好用：改文字→动 HTML；改好看→动 CSS；改"会动"→动 JS。

    2.4 本地 vs 线上

    • 本地（localhost）：只在你自己电脑能看，像在自家厨房试菜。
    • 线上（公网 / 域名）：任何人输入网址都能看，像把餐厅开到大街上。

    2.5 术语表（建议收藏）

    预览 Preview：变成最终版前先看效果。
    部署 Deploy：把网站放到公网，让别人能访问。
    响应式：同一套代码手机和电脑都好看。
    Prompt：你给 AI 的"需求指令"，最值钱的技能。
    静态网站：纯 HTML/CSS/JS，不需数据库，最易部署。
    服务器：由服务商管理的、24 小时开机的公共电脑，你只往里放文件。
    API：让不同程序互相"对话"的接口（像服务员去厨房传菜）；API 密钥相当于程序的"密码"，用来授权调用服务。
    内联 CSS：把样式直接写在网页文件里（不单独建样式文件），单文件更方便分享。

    课程 / 认知篇

    第 3 章 · 你的"工作室"：零安装起步

    🎯 学习目标：理解为什么零基础不必先装软件；认识浏览器即工作台；理解"沙箱"是什么；完成第一次打开 WorkBuddy 并发消息。

    3.1 为什么不用先装一堆软件

    传统学编程第一关往往是：装编辑器、装运行环境、配路径……一步报错就劝退。Vibe Coding 的沙箱型工具把这些都藏起来了——打开网页就能用。

    3.2 浏览器就是你的工作台

    你不需要装专门的写代码软件，也不用碰那种叫"命令行"（黑底白字、靠打字输指令的窗口）的工具——本课程用不上它。WorkBuddy 这样的工具在浏览器里提供：聊天框 + 代码生成 + 实时预览。你看到的成果，直接在网页里呈现。

    3.3 沙箱是什么

    原理：沙箱（Sandbox）是一块被隔离的安全空间。AI 在这里生成和运行代码，不碰你电脑的真实文件。所以新手随便试、错了点一下重来，不用担心搞坏系统。这也是我们推荐零基础从沙箱型起步的原因。

    3.4 先搞懂：AI 聊天助手长啥样

    如果你从没用过 AI 工具，别慌，它比想象中简单：

    • 它是什么：像一个"能聊天、还能帮你写东西"的智能助手。你在输入框打字、按发送，它就回你一段话——可能是人话，也可能是代码。
    • WorkBuddy 界面大概是：一边是聊天框（你发需求、它回复），另一边是网站预览（它生成的东西实时显示在那里）。你全程看着预览做判断。
    • 它不会害你，但结果要你验收：它给的东西不一定一次就对，不对你就用大白话让它改，就像指挥一个听话但偶尔犯迷糊的同事。

    3.5 动手：第一次打开 WorkBuddy

    1. 打开 WorkBuddy（本教程以它为例；用其他沙箱型工具也可以，但界面可能不同，均以官网当前页面为准）。它可免费使用，本课程涉及的功能都不收费，注册也只需邮箱，不涉及信用卡。
    2. 注册 / 登录：具体登录方式以 WorkBuddy 当前页面为准（邮箱最常见，也可能支持微信 / 谷歌等，哪种都行，不需要信用卡）。登录后，找界面上带"＋"或"新对话 / 新建对话"字样的按钮（通常在左侧栏或顶部），点一下就会开一个空白聊天窗口——就像新建一个微信聊天。
    3. 先发一句打招呼的话，比如：你好，我是零基础，想做个作品集网站，你待会教我。
    目标达成自检：你能看到 AI 回复了，并且界面上有"输入区 + 发送按钮 + 历史消息"。这就算"工作室"搭好了。做完这步，回到本教程点「✓ 完成本章」继续往下学～
    课程 / 工具篇

    第 4 章 · 工具全景：三类 AI 编程工具对比

    🎯 学习目标：能说出三档工具（沙箱型/终端型/插件型）的差异与适用人群；理解"插件型"是指插件化架构（典型示意：DeepSeek Harness、Pi Agent，本课不做、仅科普）；根据自己情况选对起步工具。

    4.1 三档工具一览（按"运行形态 / 架构"分，不是质量高低）

    本节仅科普，零基础可放心跳过、直接看 4.3 第一条。你只要记住"用沙箱型（WorkBuddy）"就够了，下面两种（终端型、插件型）是给更进阶的人准备的，不用现在搞懂、更不用现在去用。
    档位运行形态 / 架构代表工具适合谁
    沙箱型在隔离的云端/浏览器沙箱里运行，零安装，不碰你电脑WorkBuddy、Codex（云端）纯小白首选
    终端型运行在命令行（终端，就是那个黑底白字、靠打字输指令的窗口），直接操作你本地项目文件Claude Code（同类：Codex CLI、Gemini CLI）想精细控制本地项目、懂命令行的人
    插件型智能体本身采用插件化架构——能像手机装 App 一样，往里加不同的功能模块（工具/模型/记忆/流程）DeepSeek Harness、Pi Agent（仅作架构示意，不代表推荐使用；都是进阶工具，做作品集用不到，先了解即可）想高度可定制、按需拼装能力的人（本课不做，仅科普）

    4.2 它们到底差在哪

    • 沙箱型（WorkBuddy）：自带隔离运行环境，生成物直接在预览里看，不碰本机，最安全省心。✅ 本课程主线。
    • 终端型（Claude Code）：直接在本地命令行读写项目，灵活但要会一点命令行，且因能改你电脑文件要更小心。
    • 插件型（DeepSeek Harness、Pi Agent，进阶）：关键在于"整个智能体由插件组成"——你能往里插不同的工具、模型、记忆和流程，扩展它的本事，像手机装 App。它和前两者的区别不在"长在哪"，而在"内部是怎么搭出来的"。零基础不用管它，知道有这回事就行。
    进阶科普 · 可跳过：别把两个"插件"搞混——一种是装在写代码软件（如 VS Code）里的小工具；另一种是本课程说的"插件型智能体"，指智能体自身的架构由插件拼成（代表：DeepSeek Harness、Pi Agent，仅作架构示意、不代表推荐使用）。你不用管这个区别，记住"用沙箱型"就够了。

    4.3 选型决策树（借鉴 Odin 的"先选路"，你目前只需第一条）

    • 第一次做网站、怕配置 → 沙箱型（WorkBuddy） ✅ 就选这个
    • 想精细控制本地项目、懂命令行 → 终端型（Claude Code）
    • 想自己拼装/扩展智能体能力 → 插件型（DeepSeek Harness / Pi Agent）（进阶）
    核心认知：无论哪类工具，你做的事都一样——写清需求→看产出→提修改→验收。工具只是"你和 AI 对话的窗口"不同。学好这一套，等于学会所有工具。
    课程 / 工具篇

    第 5 章 · 核心技能：写好 Prompt

    🎯 学习目标：理解为什么 Prompt 最值钱；掌握好 Prompt 的 4 要素；能区分好坏示例；用下方生成器产出可直接发送的需求文案。

    5.1 为什么 Prompt 是最值钱的技能

    AI 不是读心术。你给的约束越具体，它瞎猜空间越小，一次出好货概率越高。这叫"减少歧义"——你表达得越清楚，世界越听话。

    5.2 好 Prompt 的 4 要素（借鉴 freeCodeCamp 的示例教学法）

    1. 我是谁（身份、求职方向）
    2. 页面模块（头像区、简介、技能、项目、联系方式）
    3. 什么风格（简洁专业 / 活泼 / 科技感）
    4. 技术约束（单页、手机电脑都好看、纯静态）

    5.3 正反例对比

    ❌ 模糊✅ 清楚
    做个好看的网站做个人作品集单页，我叫小林想转行做产品经理，要简洁专业蓝灰风，单页响应式纯静态
    加个功能在"关于我"下方加一个 3 张卡片的"项目经历"模块

    5.4 迭代式提问

    • 追加：再把卡片间距调大一点
    • 修正：颜色太暗了，换成清爽的藏青
    • 撤销：撤销刚才的修改，回到上一版

    课程 / 实战篇

    第 6 章 · 实战①：一句话生成作品集页

    🎯 学习目标：用第 5 章生成器产出文案并发送给 WorkBuddy；读懂返回的项目结构；完成本地预览；建立"先要能看的，再迭代"的心态。

    6.1 明确你的作品集目标

    回看第 1 章你拆的 4 个模块。一个通用作品集至少包含：顶部自我介绍（姓名+一句话定位）、关于我、技能/亮点、联系方式。

    6.2 把文案发给 WorkBuddy

    🔁 第一次"切 App"交接（关键）：本教程是一个网页，WorkBuddy 是另一个网站 / 另一个浏览器标签页。请现在切回你第 3 章打开的 WorkBuddy 标签页（没有就新开 workbuddy.ai 开个新对话）。把你第 5 章点过「📋 复制」的那段文案，长按粘贴进 WorkBuddy 的聊天输入框，按发送。网站会直接出现在 WorkBuddy 的预览窗口里——不在本教程里，看到预览就说明成了一半。

    粘贴第 5 章生成的需求文案并发送。它可能还会追问细节（如"要头像吗"），用大白话回答即可。

    🔑 全程统一的操作规则（很重要）：你从头到尾只在 WorkBuddy 的聊天框里用大白话下令，例如"请把页面顶部的标题改成我的名字"。AI 会改文件并给你新预览，你不用自己打开或编辑任何文件。后面所有"在 X 里加 / 改"都是"让 AI 去 X 里加 / 改"的意思。

    6.3 读懂它给的项目结构

    项目/
├─ index.html   ← 主页面（你主要改这里）
├─ style.css    ← 样式（WorkBuddy 可能把所有样式写在 index.html 里，也可能单独拆出这个文件）
└─ ...           ← 可能还有其他资源
    重点：对零基础来说，index.html 是你要最常打交道的文件。按第 5 章生成器发的指令，大概率是单文件（CSS 已内联在网页里）；但 AI 也可能拆出 style.css 等。文件多少都不影响保存：推荐用第 6.6 节方法一整包下载；若工具没有下载按钮，再用"合并单文件"兜底走方法二。不管几个文件，部署时一起上传即可。后面两章带你逐行读懂它。生成完网站后记得回到本教程继续往下学～

    WorkBuddy 会给出预览窗口，你立刻能看到网站雏形。是不是有点小激动？

    6.5 第一版的预期管理

    • 别追求一次完美。先要一个"能看的东西"。
    • 不满意就一句句提，这正是 Vibe Coding 的爽点。
    • 如果完全跑偏，说 重新来一版，要求如下… 即可。

    6.6 把网站保存到你的电脑（为上线做准备 · 此步需要电脑）

    ⚠ 此步需要一台电脑（Windows 或 Mac），手机做不了。纯手机用户请先跳过这一节，借到电脑时再回来做；前面章节都能在手机上学完。下面分两条存盘路线，外加一个"找不到导出按钮时的兜底步骤"：路线一（推荐）→ 直接导出整包；没有导出按钮时才先做"兜底"（让 AI 合并成单文件）再走路线二。

    想纯手机走 14.2 路线 0 毕业的，可以跳过本节，等借到电脑、或走 14.3 时再存。其余同学请看下面：第 14 章会讲三条部署路线，分别记为 路线 0（14.2 · WorkBuddy 一键部署）、路线 A（14.3 · Cloudflare Pages）、路线 B（14.4 · GitHub Pages，进阶可选），任选一条能成即可，不用全做。其中路线 0 通常不需要先存到电脑，但我们现在先把网站存一份当备案最稳——这样路线 0 万一不成的，立刻接路线 A 也绝不会卡住。

    方法一（推荐）：用 WorkBuddy 导出 / 下载

    ⚠ 版本提示：不同版本的 WorkBuddy 界面 / 按钮名字可能略有不同（叫"下载""导出""下载项目"都可能是它）。认准"把整个项目打包下载成一个 zip"的意思即可，不用和字面逐字对应。
    • 在预览窗口或聊天里找"下载项目 / 导出"按钮（一般在预览上方或文件列表处）。找到就点它——它会把整个项目（含所有文件）下载成一个压缩包（zip），最省心。
    • zip 一般在浏览器底部或"下载"文件夹里。Mac：双击自动解压成一个同名文件夹。Windows：右键 zip → 选「全部解压缩 / Extract All」，会得到一个同名文件夹——记住它的位置，第 14 章要"拖这个文件夹"上传。
    • 如果找不到这个按钮：别急，先用下面的"合并单文件"兜底，再走方法二，千万别直接跳到方法二（否则多文件站点会丢样式）。
    存好自检（方法一）：双击文件夹里的 index.html，能用浏览器打开看到网站就说明文件齐了；顺便看一眼里面有没有 style.css 等——部署时都要一起上传，缺一不可。

    找不到导出按钮时的兜底：先让 AI 合并成单个文件

    为什么需要这步：有的工具版本没有"导出"按钮，而且 AI 可能把样式拆成了 style.css 等好几个文件。方法二（自己存文件）一次只能稳存一个文件，所以先让 AI 把全部代码"合并进一个 index.html"，后面就变成单文件，怎么存都不会丢。
    • 在对话框输入：请把整个网站的所有代码（HTML + CSS + JS）合并进一个 index.html 文件里，CSS 全部写在 <style> 里、JS 全部写在 <script> 里，方便我下载保存。把合并后的完整代码发给我。
    • 等它发回后，再去下方方法二，把这一份单文件存到电脑即可。

    方法二（单文件）：把 AI 已发给你的那份单文件存到电脑

    ⚠ 本方法只存"一个 index.html 文件"。只要你先用上面的"合并单文件"兜底把网站压成一个文件，这里就安全；不要在"AI 还生成了 style.css、script.js 等多个文件、又没合并"的情况下直接用本方法，否则部署后会丢样式/交互。

    这是全教程唯一一次需要你自己在电脑上存文件。（还记得第 6.2 节说"你不用自己编辑文件"吗？那是指平时迭代让 AI 改就好；这里是备案动作——为了能把网站"带走、部署上线"而需要你自己存一份到电脑，平时用不到。）步骤如下：

    • 确认 AI 已把网站合并成单个 index.html（或你确认本来就只有一个文件）。直接用上面"合并单文件"兜底里 AI 已经发给你的那份完整代码，全选复制即可——不用再让 AI 发一遍。
    • Mac：打开"文本编辑"（新建一个空白文稿）→ 先按 ⌘+Shift+T 转成纯文本 → 把 AI 发给你的完整代码粘贴进来 → 菜单"文件→存储" → 在文件名框手动连写 index.html，并取消勾选"如果没有扩展名则使用 .txt"（若有这选项）→ 保存。存完看一眼文件名，结尾若是 .txt 就重命名去掉。
    • Windows：用"记事本" → 保存类型选"所有文件"、编码选 UTF-8，文件名写 index.html。
    存完自检：双击这个 index.html 文件，会用浏览器打开看到你的网站——能打开就说明存对了。打不开／打开是满屏代码乱码，多半是文件名多了 .txt（变成 index.html.txt），回去重命名去掉 .txt 即可。
    你电脑上最终应该看到：
    · 走方法一（多文件）的用户 → 一个文件夹，里面有 index.html，可能还有 style.css 等。
    · 走方法二（单文件）的用户 → 直接一个 index.html 文件就够，不用再建文件夹。
    Cloudflare 上传"文件夹"或"单个文件"都接受，但务必确认网站所需的所有文件都在里面。

    🎯 学习目标：理解 HTML 是"骨架"；认识标签/元素/属性；记住常用标签；理解语义化；能动手改一处文字看变化。

    7.1 HTML 是骨架

    HTML（超文本标记语言）用"标签"描述页面结构。标签像容器，元素是标签+内容，属性是标签上的附加信息。

    7.2 常用标签速查

    课程 / 实战篇

    第 8 章 · 读懂代码：CSS 让页面变好看

    🎯 学习目标：理解 CSS 是"装修"；认识选择器/属性/值；理解盒模型；会用实时代码沙盒改颜色、布局、圆角。

    8.1 CSS 是装修

    CSS 用"选择器{属性:值}"描述样式。例如：

    .card{ background:#fff; border-radius:16px; padding:20px; }

    意思是：所有 class="card" 的元素，白底、圆角 16px、内边距 20px。

    8.2 盒模型（借鉴 MDN，零基础必懂）

    页面上每个元素都是一个"盒子"，由内到外：内容 → padding（内边距）→ border（边框）→ margin（外边距）。间距调不好，多半是这几项没搞清。

    调试口诀：元素贴太近→加 margin；内容和边太挤→加 padding；想要边框→border。

    8.3 颜色 / 字体 / 布局（Flexbox 简介）

    • 颜色：color（文字）、background（背景），值可用 #16a34a 这种十六进制。
    • 字体：font-size、font-family。
    • 布局：display:flex 让子元素横着排，最常用。

    8.4 🛠 实时代码沙盒（在代码框改、预览框即时变）

    手机也能玩，但打代码符号（< > { }）麻烦，建议借电脑体验更顺。手机用户可先看懂规律——重点是记住"改好看 → 动 CSS"。
    ① 改大标题文字 ② 背景改蓝色 ③ 卡片加圆角 ④ 改 flex 看横排/竖排 ↺ 恢复
    提示：把预览框里的效果和你改的代码框对应起来看（电脑上代码在左、预览在右；手机上代码在上、预览在下，都一样）。
    规律："改好看→动 CSS"。沙盒里试满意后，把代码贴回 WorkBuddy 或直接用大白话让它改。

    第 9 章 · 读懂代码：JavaScript 让它动起来

    🎯 学习目标：理解 JS 是"电路/开关"；知道变量/函数/事件的概念；看懂一个简单的点击交互；明白"让 AI 加交互"即可，不必全懂。

    9.1 JS 是电路与开关

    HTML 是框架、CSS 是装修，JavaScript（JS）让页面"会动"：点击切换、表单提交、动态内容等都靠它。

    9.2 三个最基础概念

    • 变量：装数据的盒子，如 let name = "小林"。
    • 函数：一段可重复执行的指令，如 function greet(){ … }。
    • 事件："发生了什么"的触发，如"按钮被点击"。

    9.3 一个点击交互示例

    <button onclick="showContact()">联系我</button>
<script>
  function showContact(){
    alert("邮箱：hello@example.com");
  }
</script>

    意思是：点"联系我"按钮 → 触发 showContact 函数 → 弹出邮箱。

    第 13 章 · 让网站更专业：SEO / 图标 / 域名

    🎯 学习目标：知道让搜索引擎找到你的基本设置；理解 favicon；了解域名常识与"先用免费子域"；了解性能与可访问性。

    13.1 让搜索引擎找到你（基础 SEO）

    🔁 切到 WorkBuddy 那个对话窗口，在聊天框里输入下面这句（先把张三换成你自己的）：
    先说一句大白话：<head> 是网页的"头部"，放一些看不见但很重要的设置。SEO 要加的两个标签就是 <title>（浏览器标签上显示的标题）和 <meta name="description">（别人在百度/谷歌搜到你时，结果里显示的那段描述）。你不用懂原理，照下面模板发给 AI 就行——但记得先把括号里的占位换成你自己的真实信息。

    ⚠ 一定先改再发：下面例子里写的是"张三"，把张三换成你自己的名字和定位，改好整段发给 AI。嫌改麻烦也行，直接打字告诉 AI：请在 head 里把标题设成"张三 · 个人作品集"，描述设成"想转行做产品经理的张三的作品集"（同样换成你自己的）。

    在 WorkBuddy 里说（把张三换成你自己的）：请在页面的 <head> 里加上：<title>张三 · 个人作品集</title> <meta name="description" content="想转行做产品经理的张三的作品集">。AI 会改好并给你新预览。

    原理（SEO 是 Search Engine Optimization，搜索引擎优化的缩写，就是让百度/谷歌更容易搜到你）：搜索引擎靠这些标签理解你的页面。标题和描述写清楚，别人搜相关词才更容易找到你。

    13.2 favicon（小图标）

    浏览器标签页左上角的小图标。最省事的做法：直接让 AI 用你的中文名生成，例如你叫张伟就说：用"张伟"的中文名做一个简单 favicon 并接入页面。想用字母也行，就写 ZW（名字拼音首字母）——中文名是默认路径，字母可选。如果中文名生成出来挤在一起 / 不清晰，就改用名字拼音首字母（如 ZW），效果更稳。

    13.3 域名常识

    • 域名：像 yourname.com，是网站的网络地址。
    • 免费起步：部署平台会给你子域（如 xxx.pages.dev），新手先用它。
    • 想用自己的域名：再去注册商购买并绑定，属于进阶，不急。

    13.4 性能与可访问性常识

    • 图片别太大，否则加载慢。
    • 文字和背景对比度够，才看得清（可访问性）。
    • 这些都可以直接问 AI：帮我校验这个页面的可访问性并给改进建议。
    提示：本章在 WorkBuddy 里加完 SEO / favicon 后，回到本教程点「✓ 完成本章」继续，下一步我们就去把它真正上线。
    课程 / 上线篇

    第 14 章 · 免费部署上线

    🎯 学习目标：理解部署原理；用 Cloudflare Pages 或 GitHub Pages 免费上线；或让 WorkBuddy 一键部署；完成上线检查清单。

    14.1 部署原理复习

    原理：部署 = 把你的 index.html 等文件，复制到一台 24 小时开机的公共服务器（由服务商管理、你只放文件），并绑一个网址。本教程保证：跟着下面任一条路线，你都能拿到一个别人能访问的网址。

    14.2 路线 0（先试这条）：让 WorkBuddy 直接部署

    三条路线按优先级：先试 14.2（路线 0） → 不支持就走 14.3（路线 A，Cloudflare） → 想永久免费域名再说 14.4（路线 B，GitHub Pages）。任选一条能成即可，不用全做。
    走这条前，建议先按第 6.6 节把网站存到电脑当备案。若 WorkBuddy 能直接部署，这步非强制；但存一份最稳妥——万一不支持，能立刻接路线 A，绝不卡住。
    1. 在对话框输入：帮我把这个网站部署上线，给我一个可访问的链接。
    2. 如果 WorkBuddy 支持一键部署，它会直接给你一个网址——搞定，这是最省事的。
    3. 如果它说"暂不支持"（或你找不到部署入口）：别慌，关掉它，回到第 6.6 节确认文件已存电脑，直接走下面 14.3 Cloudflare——免费且 100% 能成，完全不影响你上线。所以这条不成也绝不会卡住。
    小贴士：不同工具版本能力不同，所以先试这条；不行就路线 A，两条都免费、都能拿到网址。

    14.3 路线 A：Cloudflare Pages（上传文件夹，免费 · 此步需要电脑）

    ⚠ 前置 + 最重要提醒：先把网站保存到电脑（在第 6 章往下找到 6.6 节，得到含 index.html 的文件夹或单文件）。
    ⚠ 上传前务必重新导出「最新版」：你第 7–13 章在 WorkBuddy 里加的深色模式、项目卡片、SEO 等改动，不会自动出现在第 6 章那份旧文件里。请在上传前先回 WorkBuddy，把最新版本重新走一遍 6.6 方法一导出 / 保存，确认文件夹里是最新的 index.html，不要直接上传第 6 章那份旧备份——否则上线的是没改过的初版。
    如果你全程只有手机、6.6 也没做：那这里确实需要借一台电脑（用来存文件 + 上传）；或者回到上方 14.2 看 WorkBuddy 能否直接给你链接——能的话就不需要电脑。
    1. ⚠ 先放宽心：Cloudflare 官网界面常年会改版，下面提到的按钮名字（如"Workers & Pages""Upload"）可能有出入。不用和文字逐字对齐——认准"创建网站 / Pages / 直接上传文件夹"这类意思的入口就行；一眼找不到就点页面里的"Pages"或"创建"。按意思走，别被字面对不上吓退。
    2. 打开 Cloudflare Pages。用邮箱注册（免费、不需要信用卡）→ 收验证邮件点链接 → 登录。
    3. 登录后如果弹出"Add a site / 添加站点"，先关掉或跳过——那是给"自己买域名"的人用的，和我们现在无关。然后在左侧菜单找 Workers & Pages（Cloudflare 里"创建并托管网站"的入口；Git 是程序员存代码历史的小工具，这里用不到），点右上角"创建" → 选 Pages（不是 Workers）→ 选"上传资产 / Upload"（是直接拖文件夹，不是连 Git）。
    4. 上传前会让你填一个项目名（随便起个英文短名，如 my-portfolio）；如果界面出现"构建设置"，构建命令和输出目录都留空即可（纯静态单文件不用填，没出现就直接下一步）。然后把第 6.6 节保存好的文件拖进上传区（或点"浏览"选文件）。
      ✅ 上传一定要传对层级（最重要的一步）：上传后，上传区里应该直接看到 index.html 在最外层（旁边可能还有 style.css 等）。
      ✅ 正确：index.html（最外层）
      ❌ 错误：只有一个 my-portfolio 文件夹、里面才是 index.html（这样打开网址会 404）。
      最稳做法：直接拖那个 index.html 文件进去；或多文件就先双击打开你保存的文件夹、选中里面全部文件再一起拖。确认上传区上方是 index.html 这一级，再点 Deploy。
    5. 拖进去后，必须点一下页面上的「部署 / Deploy」按钮（通常是蓝色）——光传文件不算发布，不点 Deploy 进度条不会走。进度条走完，页面会显示一个 xxx.pages.dev 网址——那就是你的真网址，点它或复制发给别人都能打开，你的网站上线了！

    14.4 路线 B：GitHub Pages（永久免费，进阶可选）

    零基础优先主路径或路线 A。路线 B 需要用到 GitHub（第 11 章提过的代码存放网站），涉及"仓库""分支"概念，略技术。只想快点上线就用前面两条；这里留着进阶。
    补几个词：仓库≈ 项目文件夹的"云端版"；分支≈ 一个版本线，新手用默认即可；GitHub Pages 是 GitHub 自带的"把仓库变网站"功能。
    1. 注册 GitHub（第 11 章认识的网站），新建一个仓库（云端项目文件夹）。
    2. 进仓库后点 Add file → Upload files。⚠ 不要整体拖"文件夹"进去——GitHub 常会把文件夹当成子目录，导致打开网址 404（白屏）。正确做法：先按第 6 章 6.6 方法一把网站合并成单个 index.html（或进入你保存的文件夹、选中里面全部文件再一起拖），确保所有文件都在仓库根目录（没有多套一层文件夹），再点 Commit changes 提交。同样记得：上传的是第 7–13 章修改后的最新版，别传第 6 章旧备份。
    3. 仓库 Settings → Pages → 选择分支（用默认 main）→ Save。
    4. 等几分钟，得到 用户名.github.io/仓库名 网址。

    14.5 上线检查清单 + 避坑

    • 上传的是含 index.html 的整个文件夹或单文件（在第 6 章往下找到 6.6 节）（跳到第 6 章）
    • 主文件名叫 index.html（部署平台默认打开它）
    • 本地预览正常后再传
    • 打不开先查文件名/路径大小写
    • 真机确认：把网址发到微信、或复制到手机浏览器打开，确认能正常显示、手机上也好看——这就算真上线了
    里程碑：做到这步，你拥有一个真实上线的作品集。写进简历、发朋友圈，这是 Vibe Coding 的第一个战利品。

    第 15 章 · 调试、避坑与结业

    🎯 学习目标：掌握基础调试思路；牢记安全与隐私红线；了解版权；拿到下一步路径；完成成果自检。

    15.1 调试思路（网站"坏了"怎么办）

    1. 先看哪里坏了：整页白屏，还是某块不对？
    2. 白屏多因 HTML 少标签 / 文件名错；某块不对多因 CSS。
    3. 把报错文字原样复制给 AI：这段代码报错了：xxx，怎么修？
    原理：调试（debug）= 让程序真实行为和预期对上。你不用懂全部，会"描述现象 + 交错误信息给 AI"就能解决 90%。

    15.2 安全与隐私红线

    • ❌ 不往任何对话框贴：密码、API 密钥（相当于程序的"密码"，用来授权调用某项服务）、身份证号、银行卡。
    • ✅ AI 工具不是保险箱，敏感信息本地保存。
    • ✅ 部署用的平台，账号密码独立、开启两步验证。

    15.3 版权

    • 用了别人的模板/图片，注明来源，确认许可允许。
    • 自己产出的内容，记得保留原文件以便修改。

    15.4 下一步学习路径

    • 想做能存数据的网站（留言板/记账）→ 了解"后端/数据库"
    • 想做小程序 / App → 同样 Vibe Coding 思路换对应工具
    • 想更专业 → 试终端型（Claude Code），或插件型（DeepSeek Harness / Pi Agent，仅作架构示意）这类可拼装架构
    • 想做复杂 / 可定制项目 → 深入了解插件型智能体的插件化架构
    • 系统深学 → 回到第 10 章推荐的开源教程（MDN / freeCodeCamp 等）
